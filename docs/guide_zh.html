KGSaveManager — 离线文档

KGSaveManager 是 Windows 上的 Kittens Game 存档管理工具，用 Python 编写，界面中英双语，不依赖任何第三方库。版本：v1.3.0。

两套前端共用同一份数据目录与配置文件：主版本是 HTML 界面 （KGSaveManager.py），在系统浏览器里显示；Tk 版是传统 Tkinter 窗口（KGSaveManagerTk.py）。本文档描述的行为两者一致（界面差异会单独说明）。

主版本（HTML 界面）

启动方式：

python KGSaveManager.py [--port N] [--no-browser] [--verbose]
  • 程序在 127.0.0.1 上提供界面，并以浏览器“应用窗口”方式打开 （Edge/Chrome 的 --app=，没有地址栏与标签页）。启动时会打印 地址，也可以在本机手动打开。
  • 窗口标题与图标由页面决定：<title> 与 webapp/assets/favicon.ico、manifest.webmanifest。 但它仍然是浏览器进程，因此在资源管理器与任务栏里归在 Edge/Chrome 名下。
  • 界面数据全部来自本地 JSON 接口（/api/state、 /api/call、/api/events），前端只使用标准库，不需要 任何第三方包。
  • 窗口尺寸：应用窗口的尺寸由浏览器按配置记住，命令行 --window-size 只在首次（干净配置）生效，因此页面会在加载时自行把窗口调整成横向并居中； 如果你已经手动调整过窗口，程序不会再改动它。
  • 界面本身是网页，所以“选择文件夹”是文本输入：粘贴路径后确认（Tk 版则是 系统文件对话框）。
  • 退出只有两种方式：页面里的「退出」按钮，或 Ctrl+C / 关闭控制台窗口。程序不会 因为页面停止响应而自行退出——浏览器会把隐藏（最小化或被完全遮住）页面的定时器降频到约 每分钟一次，「没有联系」无法与「用户离开了」区分开。
  • 在地址后加 ?selftest=1 可运行页面自检：导航、槽位表、备注、 下载选项、编辑器树与事件通道。地址还支持 ?page=saves 这类深链，直接打开某一页。

两套前端共用同一个 kgsm_data/，请不要同时运行：本地端口与配置 文件是共享的。

快速开始

Tk 版用 python KGSaveManagerTk.py 启动，页面与行为相同， 只是窗口是 Tkinter 的。界面自身不需要浏览器、也不开放本地端口，选文件夹用系统对话框 而不是文本框（游戏本身仍是网页，游玩时仍会打开浏览器）。

  1. 先读这份文档。
  2. 打开「下载游戏」页：保持默认仓库与版本，下载源先选 github.com，失败再换镜像；选择目标文件夹（默认 程序目录\KittensGame）后开始下载。需要的话勾选“下载完成后把 该目录设为服务目录”。
  3. 打开「配置」页：确认游戏目录指向含 index.html 的文件夹， 按需要设置语言与浏览器。配置改完即自动保存，没有单独的保存按钮。
  4. 打开「启动游戏」页，或首页的「启动游戏」链接：本地服务启动，游戏在新窗口 打开，游戏页面会自动连上存档桥。

界面结构

首页（KGSM）

左侧是导航（编号药丸按钮），右侧是主要内容。首页给出上手流程：下载游戏 → 配置程序 → 启动游戏，每一步都是可点击的链接；“关于”板块里有项目链接、离线文档 与更新日志入口。除首页外，各页顶部只保留一行小标题（眉题），不再重复显示大标题。

标签页

固定顺序：KGSM、启动游戏、存档管理、修改存档、下载游戏、配置。日志按归属显示： 存档相关在「存档管理」，服务与桥的事件在「启动游戏」，下载事件在「下载游戏」； 首页不显示日志。

存档管理

槽位模型与文件名

共 10 个槽位。槽位由扫描存档库决定，不写在配置里。文件名格式为 名字_1.kgsav 到 名字_10.kgsav；新槽位的默认名字是 存档N。文件名不做翻译。槽位显示格式为 “存档NN-名字”（英文界面是 Save NN-name）——列表与 下拉框使用同一格式；空槽位显示 （空）。同一槽位有多个文件时取最新的 那个。删除配置文件不会影响识别。

自动存档

用 KGSM 启动游戏，让页面连上 WebSocket 存档桥；选中槽位后点「自动存档」。 若该槽位已有存档，会先确认覆盖。游戏当前存档通过桥取回并写入槽位文件。

桥会在服务日志里标注数据来源：engine 表示读到了运行中游戏的数据， localStorage 表示引擎尚未就绪、使用的是浏览器最近一次自动保存快照。 空闲连接用 WebSocket ping 保活，所以日志里不会出现周期性断开/重连。

覆盖槽位前，原文件会先备份到 kgsm_data/backups/。

手动导入

「手动导入」弹窗顶部显示存档库文件夹（带「复制路径」按钮），可以从两条途径导入：

  • 浏览选择存档文件：调起系统文件对话框（HTML 版是浏览器的文件选择器）， 选中文件后读取并写入当前槽位。写入前会校验内容，疑似不合法时会先询问； 被选中的文件本身不会被删除或改动。
  • 下方文本框可直接粘贴存档文本，点「确定」写入。关闭窗口即取消。

存档归属哪个槽位由文件名决定（名字_1.kgsav … 名字_10.kgsav），所以也可以在文件管理器里打开这个文件夹，给文件 改名来换槽位，然后点界面上的「刷新」重新扫描。

复制存档 / 自动读档

「复制存档」把槽位内容复制到剪贴板，再到游戏里 Import 处粘贴（Ctrl+V）。 「自动读档」确认一次后把槽位内容发送到游戏页面，页面写入并自动刷新载入；弹窗会 报告页面是否确认写入，未能确认时会明确提示“已发送但未确认”，不会谎报成功。

改名与刷新

「改名」修改槽位文件名，前提是该槽位已有存档；改名不写配置。「刷新」在程序外 新增或改名文件后重新扫描存档库。

手动添加存档

不走游戏导出流程时，可以手动放进一个存档：

  1. 把导出的存档文本保存为文件，命名规则 任意名_槽位号.kgsav（例如槽位 3 用 存档3_3.kgsav）。最后一个下划线前面的部分就是槽位名。
  2. 把文件放进存档库 kgsm_data/kittens_saves/。
  3. 打开程序，在「存档管理」点「刷新」（或切到该标签页）即可看到。

备注与异常检查

备注按槽位保存在配置文件里。「检查异常文件」会列出不符合命名规则的文件与内容 为空的存档文件。

修改存档

数据来源

可以打开槽位文件，也可以读取运行中的游戏（实时模式经存档桥取档）。打开文件时 会先在 backups/ 里生成一份 .bak 备份再进入编辑。

视图与源码

编辑器用两种视图显示同一份数据，工具栏左侧的分段开关切换（视图/源码），右侧是 打开/写入。视图模式是键值树：对象键显示原名；数组元素带下标，元素是对象时会附上 它的第一个键值（例如 0 · name: Ironworks），标量元素只显示下标与值。 节点前的三角标或键名可以折叠/展开——默认只展开根那一层，其余全部收起，编辑后 重新渲染仍保持折叠状态。点叶子节点的值可以修改，JSON 类型自动识别，无法解析的按 字符串保存。源码模式显示带缩进的 JSON，保持键序、不做排序。

写入与备份

「写入」把数据重新编码成游戏使用的 lz-string Base64 格式，并原子替换槽位文件。 实时模式下「写入」把存档下发给游戏页面，页面刷新后载入。

启动游戏与本地服务

服务与存档桥

服务把配置的游戏目录发布在 127.0.0.1 上；HTML 响应会在内存里插入 bridge.js，磁盘上的游戏文件不会被修改。存档桥在另一个端口上监听， 页面刷新后会自动重连。

浏览器使用

只有「启动游戏」会新开一个浏览器窗口；超链接在当前浏览器中打开。所有链接都使用 配置里指定的浏览器；“使用系统默认”会在运行时解析系统默认浏览器。

下载游戏

仓库与下载源

可选两个 GitHub 仓库：作者原版（nuclear-unicorn/kittensgame）与 社区版（kitten-science/kittensgame）。下载源有 github.com（直连）与镜像代理（ghproxy.net、 ghfast.top、gh-proxy.com），镜像返回的是同一个文件。

版本列表

这些仓库没有发布 release 标签，因此版本列表给出的是仓库默认分支（即最新版）以及 真实存在的 release 标签；开发分支不列出。

连通性测试

「测试连通性」会并行检查所有下载源（短超时），逐个给出 OK 或 FAIL。

下载流程

zip 先下载到目标文件夹下的 .temp；若目标文件夹里有文件，会先确认 并清空。解压后摊平唯一的顶层目录，并要求根目录存在 index.html。 完成时会删除 .temp，除非取消勾选“下载完成后删除临时下载文件”。

配置

各项说明

  • Language：中文或英文，标签本身始终显示为英文。
  • 游戏目录：含 index.html 的文件夹，本地服务与下载器都用它。
  • 固定端口：本地服务使用的端口。留空表示自动分配——自动分配到的端口会 写回这一项并在之后沿用；如果下次启动时该端口被占用（被别的程序或另一份本程序 占用），本次会退回自动端口，在启动日志里说明，并把新端口记下来。
  • 浏览器：打开游戏页面与外部链接使用的可执行文件；留空表示系统默认。

配置页不需要点保存：「游戏目录」「固定端口」「浏览器」改动后自动写入配置文件， 界面左下角提示的路径就是配置文件位置。

语言

界面支持中文与英文；没有配置文件时按系统语言选择。Language 标签本身始终显示为 英文。

外部翻译文件

不改程序也能加翻译：把文件放到程序旁边的 i18n/ 文件夹即可，支持 两种格式。

JSON，推荐结构：

{
  "zh": { "tab.saves": "存档管理" },
  "en": { "tab.saves": "My Custom Saves" }
}

也接受单语言的 JSON，语言由文件名推断（zh* 为中文，其余为英文）。 例如 zh.json：

{ "sv.btn_auto_save": "自动存档" }

PO 文件使用 msgid/msgstr 配对，例如 en.po：

msgid "sv.btn_auto_save"
msgstr "Auto Save"

英文示例（en.json）：

{ "sv.btn_auto_save": "Auto Save", "dl.btn_download": "Fetch Game" }

内置表中没有的键会被新增，已有的键会被覆盖。

键来自哪里：内置中英文字符串定义在 i18n.py 的 STRINGS 里，分别是 _ZH 与 _EN。想改任何 界面文字，用同一个键在外部文件里覆盖即可。程序使用的键前缀：

前缀位置示例
tab.*标签页标题tab.saves, tab.settings
eb.*页面眉题（等宽小标题）eb.saves, eb.settings
kgsm.*首页kgsm.guide_title, kgsm.step_doc
sv.*存档管理sv.btn_auto_save, sv.btn_load
la.*启动游戏la.btn_start, la.log_title
st.*配置st.game_dir, st.browser
ed.*修改存档ed.btn_open, ed.value_title
dl.*下载游戏dl.mirror, dl.btn_test
dlg.* / err.* / msg.*对话框、提示、日志dlg.no_file, err.no_dir
tag.*日志标签tag.start, tag.done

想确认某个界面文字对应的键，打开 i18n.py，在 _ZH 里 搜这段文字即可。

离线文档跟界面语言一致：中文界面下“关于”打开 docs/guide_zh.html，否则打开 docs/guide_en.html； 更新日志同理取 CHANGELOG_zh.md 或 CHANGELOG.md。把同名 文件放进 i18n/ 会优先于随包文档，因此可以不改程序就替换成自己的翻译版 （例如 i18n/guide_zh.html 或 i18n/CHANGELOG_zh.md）。

浏览器

首次启动会自动检测浏览器；可以用「浏览」选择可执行文件，也可以重置为系统默认。

路径与引号

保存时会规范化路径：去掉首尾引号、分隔符统一成反斜杠，所以 "C:/Games/KG" 与 C:\Games\KG 都能用。

端口

端口可留空，留空即自动分配（并在首次使用后记为固定端口）。“关于”板块提供项目链接、 离线文档与更新日志入口。

数据与日志

目录结构

程序目录/
├─ KGSaveManager.py
├─ i18n.py / config_store.py / web_server.py / web_bridge.py
├─ savecodec.py / downloader.py
├─ pages_download.py / pages_editor.py / pages_manual.py  （视图）
├─ ui_tk.py                     （Tkinter 界面端口实现）
├─ core/                        （与界面无关的逻辑：ui_port / slots / flows）

├─ docs/guide_zh.html / docs/guide_en.html
├─ CHANGELOG_zh.md / CHANGELOG.md
└─ kgsm_data/
   ├─ kittens_saves/   存档库
   ├─ backups/         带日期的备份，名字.kgsav.YYYYMMDD_HHMMSS.bak

运行日志

每次启动新建一个日志：kgsm_log/YYYYMMDD_HHMMSS.log，记录程序版本、 平台、Python 版本、配置摘要、服务与桥的启停、存档与下载操作，以及错误。

常见问题

  • 浏览器一栏为空：表示“使用系统默认”，“配置”页的提示会显示检测到的浏览器。
  • 提示“游戏页面尚未连接”：请用 KGSM 启动游戏；必要时刷新游戏页面。
  • 下载失败：换一个下载源，或先做连通性测试。也可以启用加速器并使用 github.com。若某个源返回 HTTP 5xx，换其他源即可——镜像之间是 相互独立的第三方代理，会各自失败。
  • 下载日志出现“GitHub API 不可用（可能触发限流），已实测默认分支：…”： 未登录的 GitHub API 每 IP 每小时 60 次，因此版本列表退回实测分支的方式， 下载不受影响。
  • 提示“处理存档失败”并给出运行日志路径：界面内部出现了未预期的错误，弹窗与 kgsm_data/kgsm_log/ 里有详细信息。
  • 提示“存档可能/疑似不合法”：这段文本无法按 Kittens Game 存档解码，确认内容 正确时再继续。
  • 退出：侧栏左下角的「退出」会先确认，然后停止本地服务并关闭程序（应用窗口会 一并关闭；如果是在普通浏览器标签页里打开的，页面会提示可以手动关闭）。

打包 EXE

pip install pyinstaller
pyinstaller KGSaveManager.spec

产物：dist/KGSaveManager/KGSaveManager.exe。spec 里声明了全部模块， 并把 docs/ 一起打包。

测试

python -m unittest discover -s tests -t .

测试只用标准库，不访问网络、不启动真实浏览器。覆盖范围：存档编解码（在本地有 Node.js 与游戏源码时，会与游戏自带的 lib/lz-string.js 做一致性校验）、 下载器解压与镜像配置、WebSocket 桥协议与保活、注入脚本（DOM 元素误判、延迟绑定 引擎、存档来源标注）、配置备注、槽位写入、翻译表，以及 HTML 页面在真实无头浏览器里 的自检（布局、样式、手动导入弹窗、编辑器折叠等）。静态检查会在遗留未使用的 import、 未被引用的函数或没有引用的翻译键时让测试失败。

关于

KGSaveManager 用于在 Windows 上管理 Kittens Game 存档，提供存档槽位、自动存档与 手动导入、存档编辑器、带存档桥的本地 Web 服务，以及游戏下载器。界面支持中文与英文， 并支持外部翻译文件。
