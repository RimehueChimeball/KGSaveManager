KGSaveManager — Offline Guide

A Windows desktop companion for Kittens Game: bilingual UI (English/中文), 10 named save slots, a local web server with a save bridge, a save editor, and a game downloader. Zero third-party Python dependencies. Version: v1.1.0.

Quick Start

  1. Read this guide. The home page links here under “Getting Started → Read the offline guide”.
  2. Get the game. Open the Download Game tab, keep the default repository and version, pick github.com first (switch to a mirror if it fails), choose a folder (default: program\KittensGame), and press Start Download. Optionally tick “use this folder as the service directory”.
  3. Configure. Open Settings: check the game directory (pointed at the folder containing index.html), language, browser, and optionally a fixed port.
  4. Launch. Open Launch Game (or “Launch the game” on the home guide) to start the local server and open the game in a new browser window. The game page auto-connects to the save bridge.

Interface

Home (KGSM)

The home page has no launch widgets anymore. On the left, buttons list every page except the home page for one-click navigation. On the right, the Getting Started flow walks you through: read the guide → download → configure → launch. You can switch pages anytime via the left buttons or the top tabs.

Tabs

Fixed order: KGSM → Launch Game → Save Management → Edit Save → Download Game → Settings. Logs belong to their own page: save actions in Save Management, server/bridge events in Launch Game, download events in Download Game; the home page shows no logs.

Save Management

Slot model & filenames

Ten slots. A slot is identified by scanning the save library, not by config: files look like name_1.kgsav … name_10.kgsav where name is the slot name (default 存档N, kept as-is — filenames are never translated). The slot label shows a translated prefix (Save 01. / 存档01.) plus the filename prefix. Empty slots show empty. If several files match a slot, the newest wins. Deleting the config file never breaks recognition.

Auto save

Launch the game through KGSM (the injected page connects to the local WebSocket bridge). Then click Auto Save on the selected slot. KGSM confirms when overwriting, pulls the game’s current save over the bridge, and writes it directly to the slot file — no clipboard, no temp step.

Manual save

Manual Save opens a dialog with two parts:

  • Top: the temp folder path with a Copy Path button (the path is not copied automatically). Drop the game’s exported file into this folder — once detected (and stable) the save is written, the window closes by itself, and a “save detected” notice appears.
  • Bottom: a large box to paste the exported save text, then press OK. Pasting is format-checked first; if the content “may/might be invalid” you are asked before saving. Close cancels.

Copy save / load

Copy Save copies the selected slot’s text to the clipboard — paste it into the game’s Import (Ctrl+V). Auto Load (from the game side) asks once in KGSM (“this overwrites current progress”), then sends the save to the page, which stores it and reloads automatically.

Rename & refresh

Rename renames the slot’s disk file (name_1.kgsav → newname_1.kgsav); the slot must have a save first. Renaming never touches config. Refresh rescans the library after you add or rename files outside the program. The slot list scrolls with the mouse wheel.

Notes & checker

Notes are saved automatically per slot inside the config file (the only slot-related data the config stores). Check Abnormal Files lists files the program does not manage (unparsable names, leftovers in the temp folder, empty saves).

Save Editor

Sources

Open a save slot (file) or the running game (live) — live pulls the current save over the bridge. Opening a file first creates a .bak backup next to it.

View & source

Two displays of the same data: View shows a key/value tree (dictionary keys as-is; arrays as index0, index1, …). Double-click a leaf to edit its value (JSON types are auto-detected; unparsable text is stored as a string). Source shows pretty-printed JSON, preserving key order (no sorting).

Write & backup

Write re-encodes (lz-string Base64, same format the game exports) and atomically overwrites the slot file, or — in live mode — sends the whole save to the game, which reloads it. Whole-save replacement is the current live-editing model.

Launch Game & Web Server

Local server & bridge

The server serves the configured game directory on 127.0.0.1 only. While running, HTML responses are injected in memory with bridge.js (your game files are never modified) and a local WebSocket bridge starts on a separate port. The page reconnects automatically after refresh.

Browser rules

Only launching the game opens a new browser window; hyperlinks open normally in the same browser. The configured browser (Settings → Browser) is used everywhere; “system default” mode resolves the real default browser at runtime.

Download Game

Sources & mirrors

Two repositories, both from GitHub: the author’s original (nuclear-unicorn/kittensgame) and the community fork (kitten-science/kittensgame). The download source list: github.com (direct) plus mirror proxies (ghproxy.net, ghfast.top, gh-proxy.com) that fetch the same file when GitHub is blocked or slow.

Versions

These repos publish no real releases. The version list therefore shows only the repository’s default branch (the latest version) plus any genuine release tags. Development branches (dev/, chore/, dependabot/, …) are hidden — they are not playable versions.

Connectivity test

Test Connectivity probes every source in parallel (HEAD, ~6 s timeout) for the current version and shows OK/FAIL per source, so you can pick the fastest working mirror.

Download flow

Destination folder defaults to program\KittensGame. If it already contains files you are asked to confirm before continuing (content is cleared). The zip downloads into .temp under the target (never the app data temp), is unzipped with the single top folder flattened away, and index.html must exist at the root. “Delete temporary download files after completion” (default on) removes the .temp folder. Optionally the folder is set as the service directory when done.

Settings

Language & external i18n

UI language: zh / en. When no config exists the system language is used. The Language label stays English by design. You can add external translations: put *.json (either {"zh":{...},"en":{...}} or a single-language map) or *.po files into an i18n/ folder next to the program; they are merged on startup. Language is inferred from the filename (zh* → Chinese, otherwise English).

Browser

Auto-detected on first start. Browse to pick an .exe, or reset to “system default”.

Paths & quotes

Pasted paths are cleaned automatically: surrounding quotes (as Windows copy adds) are stripped and separators are normalized to backslashes, so both "C:/Games/KG" and C:\Games\KG work.

Port & home slot

Fixed port — empty means auto-pick. Home save slot is the slot used by the copy-and-launch helpers. The bottom “About” area links to the project and the author’s GitHub profile (labels are intentionally not translated).

Run logs

A new log file is created at each launch: kgsm_log/YYYYMMDD_HHMMSS.log. It records startup info (version, platform, Python, config summary), web server & bridge start/stop, save and download activity, and errors — useful when reporting issues.

Troubleshooting

  • Nothing opens when using “system default” browser: the empty entry means “system default” and is intentional; the Settings hint shows the detected browser. Try the Connectivity Test on the download page if the network is involved.
  • “Game page not connected”: launch the game via KGSM and wait a moment, or reload the game page — the bridge reconnects.
  • Mirror download fails: switch source or run the connectivity test; or enable your accelerator and use github.com.
  • “Save may/might be invalid”: the text did not decode as a Kittens Game save; only proceed if you are sure.
  • Inputs steal focus: press Esc to drop focus; switching pages returns focus to the notebook.

Building the EXE

pip install pyinstaller
pyinstaller KGSaveManager.spec

Output: dist/KGSaveManager/KGSaveManager.exe. The spec declares all split modules explicitly and disables UPX.
