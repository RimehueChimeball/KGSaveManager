KGSaveManager — Offline Guide

KGSaveManager is a save manager for Kittens Game on Windows (Python + Tkinter, bilingual UI, zero third-party dependencies). Version: v1.2.0.

Quick Start

  1. Read this guide.
  2. Open the Download Game tab. Keep the default repository and version. Select github.com as the source; if it fails, select a mirror. Choose a destination folder (default: program\KittensGame) and start the download. Tick “use this folder as the service directory” if desired.
  3. Open Settings. Verify the game directory points to the folder that contains index.html. Set language and browser if needed.
  4. Open Launch Game or use “Launch the game” on the home page. The local server starts and the game opens in a new browser window. The game page connects to the save bridge automatically.

Interface

Home (KGSM)

The home page shows the program title. The left column lists buttons for every page except the home page. The right column shows the getting-started flow: read the offline guide, download the game, configure, launch. Each step is a link.

Tabs

Fixed order: KGSM, Launch Game, Save Management, Edit Save, Download Game, Settings. Logs appear on the page they belong to: save actions in Save Management, server and bridge events in Launch Game, download events in Download Game. The home page shows no logs.

Save Management

Slot Model & Filenames

There are 10 slots. Slots are identified by scanning the save library, not by configuration. Files are named name_1.kgsav through name_10.kgsav. The default slot name is 存档N. Filenames are never translated. The slot label shows a translated prefix (Save 01. or 存档01.) followed by the filename prefix. Empty slots show empty. If multiple files match a slot, the newest is used. Deleting the configuration file does not affect recognition.

Auto Save

Launch the game through KGSM so the page connects to the WebSocket bridge. Select a slot and click Auto Save. If the slot already has a save, confirm the overwrite. The current save is retrieved over the bridge and written to the slot file.

Manual Save

Manual Save opens a dialog with two areas.

  • Top: the temp folder path and a Copy Path button. The path is not copied automatically. Drop the exported save file into the folder. When a stable file is detected, it is written, the window closes, and a “save detected” message is shown.
  • Bottom: a text area for pasting the exported save text, and an OK button. Pasted text is validated. If the content may be invalid, the program asks for confirmation. Closing the window cancels the operation.

Copy Save / Auto Load

Copy Save copies the selected slot content to the clipboard; paste it into the game Import (Ctrl+V). Auto Load asks once for confirmation, then sends the slot content to the game page. The page stores it and reloads.

Rename & Refresh

Rename changes the slot file name. A save must exist in the slot first. Renaming does not modify the configuration. Refresh rescans the library after files are added or renamed outside the program.

Adding a Save Manually

To add a save without the game export flow:

  1. Copy the exported save text into a file named 任意名_槽位号.kgsav (for example 存档3_3.kgsav for slot 3). The name before the final underscore becomes the slot name.
  2. Place the file in the save library: kgsm_data/kittens_saves/.
  3. Open the program and click Refresh in Save Management, or switch to the Save Management tab again.

Notes & File Check

Notes are saved per slot in the configuration file. Check Abnormal Files lists files that do not match the naming rules, leftover temp files, and empty save files.

Save Editor

Data Sources

Open a save slot file, or the running game. Live mode retrieves the current save through the bridge. Opening a file creates a backup with the extension .bak before any change.

View & Source

The editor shows one data set in two views. View mode is a key/value tree. Object keys are shown as is. Array elements are labeled with the index and, when the element is an object, its first key and value (for example 0 · name: Ironworks); scalar elements show the index and the value. Double-click a leaf to edit its value. JSON types are detected automatically; unparsable input is stored as a string. Source mode shows the JSON with indentation. Key order is preserved; no sorting is applied.

Write & Backup

Write re-encodes the data to the lz-string Base64 format used by the game and replaces the slot file atomically. In live mode, Write sends the save to the game; the page reloads to load it.

Launch Game & Web Server

Server & Bridge

The server serves the configured game directory on 127.0.0.1. HTML responses are modified in memory to include bridge.js; game files on disk are not changed. A WebSocket bridge listens on a separate port. The page reconnects after reload.

Browser Usage

A new browser window is opened only when launching the game. Hyperlinks open in the current browser. The browser configured in Settings is used for all links. The “system default” option resolves the system default browser at runtime.

Download Game

Repositories & Mirrors

Two GitHub repositories are available: the author’s original (nuclear-unicorn/kittensgame) and the community fork (kitten-science/kittensgame). Download sources are github.com (direct) and mirror proxies (ghproxy.net, ghfast.top, gh-proxy.com). Mirrors return the same file.

Versions

These repositories publish no release tags. The version list contains the repository default branch (the latest version) and any genuine release tags. Development branches are not listed.

Connectivity Test

Test Connectivity checks all sources in parallel with a short timeout and reports OK or FAIL for each source.

Download Procedure

The zip file is downloaded to .temp under the destination folder. If the destination contains files, the program asks for confirmation and clears the folder. After extraction, the single top-level folder is flattened; index.html must exist at the root. The .temp folder is removed after completion unless the option is disabled.

Settings

Language

The interface supports Chinese and English. If no configuration exists, the system language is used. The Language label itself is always displayed in English.

External Translations

Translations can be added without modifying the program. Place files in the i18n/ folder next to the program. Two formats are supported.

JSON. Recommended structure:

{
  "zh": { "tab.saves": "存档管理" },
  "en": { "tab.saves": "My Custom Saves" }
}

Single-language JSON is also accepted; the language is inferred from the file name (zh* means Chinese, anything else means English). Example zh.json:

{ "sv.btn_save": "保存档案" }

PO files contain msgid/msgstr pairs. Example en.po:

msgid "sv.btn_save"
msgstr "Save Archive"

English example (en.json):

{ "sv.btn_save": "Save Archive", "dl.btn_download": "Fetch Game" }

Keys that do not exist in the built-in tables are added; keys that exist are overridden.

Where the keys come from: the built-in Chinese and English strings are defined in i18n.py, in the dictionaries _ZH and _EN inside STRINGS. Any UI text can be overridden by using the same key in an external file. Key prefixes used by the program:

Browser

The browser is detected on first start. Use Browse to select an executable, or reset to system default.

Paths & Quotes

Paths are normalized when saved. Surrounding quotes are removed and separators are converted to backslashes, so "C:/Games/KG" and C:\Games\KG are both accepted.

Port & Home Slot

The port field is optional; empty means an automatic port. Home Save Slot selects the slot used by copy helpers. The About area links to the project and the author profile.

Data & Logs

Folder Layout

program/
├─ KGSaveManager.py
├─ i18n.py / config_store.py / web_server.py / web_bridge.py
├─ savecodec.py / downloader.py
├─ pages_download.py / pages_editor.py / save_flows.py
├─ kgsm_logging.py / utils.py
├─ docs/guide_en.html
└─ kgsm_data/
   ├─ kittens_saves/   save library
   ├─ kgsm_temp/       staging folder for manual import
   ├─ backups/         dated backups, name.kgsav.YYYYMMDD_HHMMSS.bak
   ├─ kgsm_log/        run logs, one file per launch
   └─ kgsm_config.json configuration and notes

All runtime data is in kgsm_data/. Back up by copying this folder. The Save Editor writes a dated backup (名字.kgsav.日期.bak) into backups/ each time a slot file is opened for editing.

Run Logs

A new log file is created at each launch: kgsm_log/YYYYMMDD_HHMMSS.log. It records the application version, platform, Python version, configuration summary, server and bridge start and stop, save and download operations, and errors.

Troubleshooting

  • Browser field is empty: this means “system default”. The Settings hint shows the detected browser.
  • “Game page is not connected”: launch the game through KGSM and reload the page if necessary.
  • Download fails: select another source or run the connectivity test. You may also enable an accelerator and use github.com.
  • “Save may be invalid”: the text could not be decoded as a Kittens Game save. Proceed only if the content is known to be correct.
  • Focus: press Esc to remove focus from an input. Page switching returns focus to the notebook.

Building the EXE

pip install pyinstaller
pyinstaller KGSaveManager.spec

Output: dist/KGSaveManager/KGSaveManager.exe. The spec declares all modules and includes the docs/ folder.

About

KGSaveManager manages Kittens Game saves on Windows. It provides save slots, auto and manual save, a save editor, a local web server with a save bridge, and a game downloader. The interface supports Chinese and English, including external translation files.
